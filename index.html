01. Control de versiones

¿Qué es?

Es un sistema que registra los cambios realizados en los archivos de un proyecto, permitiendo consultar su historial y recuperar versiones anteriores.

Tipos

  • Local: guarda las versiones en el equipo.
  • Centralizado: utiliza un servidor central para almacenar el historial compartido.
  • Distribuido: cada usuario puede disponer de una copia completa del historial del proyecto.

Características, ventajas y desventajas

Permite comparar cambios, trabajar en equipo y recuperar versiones. Los sistemas distribuidos facilitan el trabajo sin conexión, aunque requieren aprender sus comandos.

Funcionamiento y rastreo de cambios

Se registran modificaciones mediante confirmaciones (commits), se crean ramas para trabajar en funciones y se integran los cambios mediante fusiones (merges).

Ejemplos

Git, GitHub, GitLab y Subversion (SVN).

02. Persistencia y acceso a datos

Definición

Es la capacidad de conservar información para que pueda utilizarse después de cerrar una aplicación.

Formas de persistencia

  • Archivos: guardan documentos, imágenes y configuraciones.
  • Bases de datos locales: almacenan información en el dispositivo, como SQLite.
  • Bases de datos remotas: guardan datos en servidores accesibles mediante servicios web.

Tipos de datos

Texto, números, fechas, imágenes, documentos y registros relacionados.

Mecanismos de acceso

Bibliotecas de clases, clases de SQLite y ORM, que permite relacionar objetos del programa con tablas.

Autenticación y servicios web

La aplicación verifica la identidad del usuario y utiliza solicitudes HTTP para consultar o enviar información a un servidor. Se recomienda utilizar HTTPS.

Ejemplos

SQLite, Firebase y Room.

03. Gestión de sensores

Definición

Los sensores son componentes que detectan información del entorno o del movimiento del dispositivo móvil.

Tipos

  • Acelerómetro: detecta aceleraciones y movimientos.
  • Giroscopio: mide movimientos de rotación.
  • GPS: permite obtener la ubicación.
  • Proximidad: detecta objetos cercanos.
  • Luz ambiental: mide la iluminación.
  • Brújula: ayuda a determinar la orientación.

Proceso de gestión

1. Habilitación del sensor y permisos necesarios.

2. Obtención de los datos.

3. Procesamiento e interpretación de la información.

4. Presentación de resultados al usuario.

04. Uso de recursos multimedia

Definición

Consiste en integrar diferentes medios de comunicación para mejorar la experiencia de una aplicación.

Tipos de recursos

  • Imágenes: fotografías e ilustraciones.
  • Audio: música, sonidos y grabaciones.
  • Video: contenido audiovisual.
  • Animaciones: movimientos de elementos gráficos.
  • Elementos dinámicos: interfaces interactivas.

Estructura del proyecto

Los recursos pueden organizarse en carpetas como res/drawable, res/mipmap y res/raw en proyectos Android.

Componentes de software

ImageView, MediaPlayer, ExoPlayer y componentes de animación.

05. Servicios y notificaciones

Definición

Son funciones que permiten realizar procesos y comunicar información al usuario.

Tareas en segundo plano

Son operaciones que se realizan sin mantener una pantalla abierta, respetando las restricciones del sistema operativo.

Notificaciones

Son mensajes que informan al usuario sobre eventos, recordatorios o actualizaciones.

Implementación

  • Proveedores de contenido: permiten compartir datos entre componentes de Android.
  • Tareas en segundo plano: pueden administrarse con herramientas como WorkManager.
  • Notificaciones: se crean mediante los servicios de notificación del sistema.

Servicios en la nube

Firebase, almacenamiento en la nube y servicios web.

06. Librerías y toolkits

¿Qué es una librería?

Es un conjunto de funciones y herramientas que pueden reutilizarse en un programa.

¿Qué es un toolkit?

Es un conjunto de herramientas y componentes que facilitan la construcción de aplicaciones.

Ejemplos de librerías

  • Retrofit: comunicación con servicios web.
  • Glide: carga de imágenes.
  • Room: persistencia de datos.

Ejemplos de toolkits

  • Android SDK: herramientas para Android.
  • Flutter: desarrollo de interfaces multiplataforma.
  • React Native: desarrollo móvil con JavaScript.

07. Depuración y seguridad

Depuración

Es el proceso de identificar, analizar y corregir errores en el código de una aplicación.

Seguridad

Consiste en proteger los datos, las cuentas y los recursos de una aplicación frente a accesos no autorizados.

Herramientas de depuración

  • Debugger de Android Studio.
  • Logcat para consultar registros.
  • Android Profiler para analizar el rendimiento.

Buenas prácticas

Utilizar HTTPS, validar datos, proteger credenciales, solicitar permisos necesarios y mantener las librerías actualizadas.
